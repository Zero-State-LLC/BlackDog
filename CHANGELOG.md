### Security

- Human triage of a D3-H2 halt counts only with an OpenSSH Ed25519 signature in namespace `faustcoder-triage-v1`, verified with `ssh-keygen -Y verify` at both the grader-written `appended_at` and `triaged_at`. Those times, and `valid-after` / `valid-before` / `-Overify-time`, are UTC. The verifier is the absolute path `/usr/bin/ssh-keygen` (the constant `SSH_KEYGEN_PATH`), a root-owned regular file that is not group- or world-writable and not a symlink. `PATH` is not consulted, and the version check runs that binary rather than `ssh -V`. A timeout is a refusal. The allowed-signers file is `/etc/faustcoder/triage-allowed-signers`, root-owned, mode `0644`. Each line is one principal with a UTC `valid-after`. A second principal, a pattern character (`*`, `?`, `!`, `,`), a duplicate key, a missing or unparseable `valid-after`, a missing or misowned list, an unknown key, a bad signature, a parse error, a missing `ssh-keygen`, or OpenSSH older than 8.7 leaves the halt in place. OpenSSH is checked when P3 starts. One reviewer clears an ordinary halt. A late halt needs two distinct principals and two distinct key fingerprints. The same principal twice counts once. The same key twice counts once. The recorded writer is the drop-file owner, read with `fstat` on an `O_NONBLOCK | O_NOFOLLOW` fd. A symlink, a FIFO, a hard link, or a drop owned by `fc-grader` or root, does not clear a halt. A `v:1` line and a run-key MAC alone do not clear a halt. P3 refuses to start unless the process is the dedicated `fc-grader` account, not uid 1000, and not an enrolled reviewer. A software key is enough, including for Danny's key. Spec 001 is 0.3.11.

- Audit triage folds reserved actor and OS-user names with NFKC, casefold, and a small confusable skeleton before matching `fc-grader` and `root`. `FC-GRADER`, `Root`, fullwidth letters, and a non-breaking hyphen in `fc-grader` are refused. `triaged_at` must be RFC 3339, at or after the latest `halted_at` among halt reports that name that disagreement, and no later than now plus five minutes, on write and on read. A stamp that cannot be converted to UTC, including `0001-01-01T00:00:00+14:00` and `9999-12-31T23:59:59-12:00`, is refused. On read that line is a refused triage instead of `OverflowError`. A halt with no usable `halted_at`, including a legacy halt, cannot be cleared. A MAC'd triage line that fails those checks is reported (`AuditReportLog.refused_triages`) and does not make the report log unreadable. It does not clear the halt. The gate stays closed until a valid triage exists. (#67, `665d73b`; closes #65.)

- Audit triage strips `triaged_by`, requires a non-empty printable name of at most 128 characters, and requires `triaged_at` to be RFC 3339, on write and on read. The writing OS user (`writer_uid` and `writer_user`, from the effective uid) is stored under the report MAC. A triage whose actor or recorded OS user is `fc-grader`, the dedicated grader uid, or root is refused and does not clear a halt. `rl_batch` is private (`_rl_batch`); `rl_batch_from_records` is the only public batch builder. (#63, `75d2bed`.)

### Added

- D3-H2 sampled rerun audit (spec §26 0.3.9), before P3: every passing row, a ceil(5%) sample of graded `0.0` rows (`fail` and `source_attributed`, at least one when any exist), and every signed canary are rerun from source. The seed is HMAC-SHA256(run key, "d3-h2-seed" || run id); any other seed is refused. The report records the seed and the sample ids. A disagreement leaves that row ungraded, claims the group `dropped:audit`, and persists a halt. A group already claimed `used` is reported `late` and still halts. A rerun that crashes, or that returns a non-`str` (including a `str` subclass), is a disagreement. The report is MAC'd under the run key. `rl_batch_from_records` refuses unless the latest persisted report is clear. Triage recorded against each disagreement is the only clear; another seed does not clear a halt. The audit refuses a row that fails the H1 HMAC check and does not rewrite a stored pass or fail. A row signed before the `canary` field is refused on load. T10 rows carry an explicit `example_id`, the signed record id. `rl_batch` accepts only a real `dict`, so a mapping cannot check one receipt and emit another. (#57, `63aac31`.)

The library does not generate, print or log key bytes. Every load re-checks the MAC, the grader and harness pins, the allowlist, the source hash, the full task digest, and the reference and profile, then calls `grade_receipt` with no `rerun`, `known_good` or `triage`. `passed` is true only when `metrics.failures` is empty, including at sign time. `rl_batch_from_records` takes the expected run id and the allowed policy checkpoints, keeps a complete group, scores an A1 member `0.0`, and drops a group with a missing, duplicate, ungraded or quarantined member. The consumed log does not re-enter that group. A stale pin is not regraded into training. Holds created by the record re-check carry `row_record_id` and `group_id`. ### Fixed

- `ConsumedLog.claim` refreshes an audit anchor only over the exact pre-append bytes plus the one claim line it just wrote. A line injected between the append and the refresh is not signed. A claim on a log with no anchor is refused when a MAC'd report for that run is already beside the log, and still appends when no report exists yet. If that directory cannot be listed, the claim is refused instead of assuming no report. The refresh also refuses when the anchor disappears after the pre-append read. (#61, `2f1caba`.)

- Rebinding an audit anchor is private (`_refresh_anchor_bind`) and checks the existing anchor MAC before it rewrites the bind. A caller cannot re-sign a consumed log whose halt marker was deleted: the file must be the bytes that MAC covers, or those bytes plus a suffix. Advancing the anchor re-checks that MAC under the consumed-log lock before it writes a halt marker or a new bind. A report after the first one refuses a missing anchor instead of minting a new one over the truncated log. (#60, `24170c3`.)

- A D3-H2 halt writes a MAC'd halt-marker claim into the consumed log, including when every disagreeing group was already `used`. The marker is inside the claim bytes the anchor MAC covers, so splicing the previous anchor back and restoring the report prefix does not clear the halt. Deleting the report and the anchor line leaves the marker, and a new chain is refused while that halt is unresolved. `ConsumedLog.claim` requires `run_key`. Before it appends, it checks the existing anchor MAC against the pre-append log bytes, and a mismatch or a wrong key raises before any write. The claim then refreshes the anchor bind. (#59, `ac0326f`; closes #58.)

- The D3-H2 clear report binds the sorted record ids it covered and the consumed log beside it. `rl_batch_from_records` refuses a row outside that set, including after an empty audit or a subset that leaves out a canary, and it refuses a different consumed log. Report lines form a hash chain with a sequence counter. The high-water mark is anchored in the consumed log, and that anchor MAC covers the claim bytes, so splicing an older anchor back onto a log that has grown is refused. Truncating the report file alone does not restore an older clear line. A `dropped:audit` claim left behind after the report and the anchor are removed blocks a new audit. (#57, `63aac31`.)

- A reload of a `source_attributed` native stack-overflow row remints the sealed Faust match from the stored diagnostics and native receipt. If that evidence does not reconstruct, the row stays ungraded. A signal receipt is not returned as the opposite pass or fail. A compiler row whose regrade does not match its stored outcome is dropped, and that stored outcome is not rewritten to pass or fail. A row signed before `diagnostics` and `native_diagnostics` were part of the record is refused on load. The consumed log is created with `O_EXCL` and its parent directory is opened with `O_DIRECTORY` for the fsync. `rl_batch` keeps two id-less grades of the same program, and the duplicate check holds within a single call (spec §26).

- `rl_batch` refuses a duplicate row. The marker is the minted receipt plus any `example_id`, `record_id`, or `group_id` plus `member_index`. A copied row, or one receipt under two example ids, is refused. Two separate grades of the same program are kept. A non-string `example_id` is refused. The process-local seal binds `task_digest_full`, the whole task, so the same passing envelope does not match a different prompt. A stored `harness_digest` is checked against the current pin, including a compiler-kind envelope that still carries a harness, profile, reference or stimulus. A group with a quarantined member cannot come back as a clean G-1 after a restart, including after triage resolves the hold. `rates.json` is rewritten under a file lock so two writers cannot drop each other's windows. A reload does not observe A7 rates again. A NUL byte in `faust --pathslist` raises `SandboxError` instead of an uncaught `ValueError`. The consumed log is read to EOF and appended with `O_APPEND`. Reward, consumed and quarantine files are created mode `0640`. A reward keyring cannot be pickled, uid 0 cannot load the root key, and a non-regular file or a writable or symlinked parent directory is refused.

- Grader: a bare exit-1 `ERROR : stack overflow` line stays ungraded and quarantined unless a sealed Faust 2.88.0 `faust-cli` cpp receipt exits exactly 1 with that same line. A `triage="source"` string, and any recorded triage decision, cannot turn an unattributed 124, 125, 126 or crash into 0.0 while A2-T is unimplemented. A harness or infrastructure `TriageDecision` drops a remote-import or source-size score. A compiler receipt with `termination_signal` set stays ungraded. Native mint accepts `exit_code` only when `type(exit_code) is int` and the value is 1, and it checks every `-lang` in the command. A command that omits `-lang` is refused. `apply_signal` refuses a receipt minted for an unrewardable task, including a tuple `classes` entry. `UngradedRateTracker.load_state` restores `baseline`. The unused `reward_profile_allowlist` helper and the dead `_source_tag` stage argument are gone.

- Faust directory queries read stdout as bytes and decode it with `os.fsdecode` (`surrogateescape`). A `--pathslist` line that is not decodable, including a nonexistent path that carries a byte such as `0xec`, raises `SandboxError` instead of `UnicodeDecodeError`. A well-formed absolute path that is not on disk is still returned so the mount can cover it.
