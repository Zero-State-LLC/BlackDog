# Shipwright pluck repair — 2026-10-24

The original pluck binds frequency to physical string length, gate to damping, and leaves excitation unbound. A separately identified derivative now uses pm.ks(pm.f2l(freq)+0.05, 0.01, pm.impulseExcitation(gate)). It retains the original freq/gain/gate UI names, defaults and ranges, including 20–8000 Hz. The added 0.05 offsets the exact pinned ks internal lengthTuning subtraction. The explicitly recorded pm.maxLength override increases 3 to 17.05 metres to cover the 20 Hz endpoint. Original source and closure evidence remain unchanged. The selected damping is a proposed design choice requiring independent semantic review.

Independent local verification confirmed 40 native cases at 44100, 48000, 96000 and 192000 Hz. Each is a two-second history. Static frequencies are 20, 50, 110, 440, 1000, 4000 and 8000 Hz with two gate-on intervals; additional cases check zero gain, zero gate and half gain. Generated interfaces have zero inputs and two outputs. Outputs are finite, stereo-identical and nonzero exactly when gain and gate permit excitation. Half-gain samples match float32-rounded scaling of the corresponding baseline.

The initial gain oracle mistakenly compared float32 subnormal outputs with unrounded Python binary64 half-amplitude values. All 21718 mismatching values in the first rate were subnormal-rounding cases, and every one matched explicit float32 rounding. Correcting the oracle required no DSP change. It does not weaken the binary32 contract.

These checks do not prove exact pitch, live frequency modulation, perceptual quality, arbitrary gate histories, polyphonic host compatibility, WASM behavior, or independent semantic acceptance. In particular the pinned reflection filter and waveguide delays can affect pitch. Follow-up should measure frequency response/pitch over the full original range and verify the host contract before treating the proposed repair as production-qualified.
